当前生产上限：

| 资源 | 上限 | 计量方式 |
|---|---|---|
| 单个 OJN 源 | 64 MiB（67,108,864 bytes），等于上限可读 | 完整输入包括加密外壳、所有难度、内嵌图片和末尾字节。seek 流检查已打开流的完整 Length；不因只选择一个难度忽略其他载荷占用。 |
| 一次解码生成的输入事件 | 1,000,000，等于上限可读 | 每个非零原始采样引用、有效正 BPM 和正小节长度写入，在加入集合之前计数。全难度共享计数；ReadChart 仅计所选难度实际解析的事件。 |

这是项目的支持范围，不是 OJN 格式标准或播放时长上限。长条头/尾、孤立尾、自动音频事件、
重复替换同一小节长度都计入，之后配对、移除或替换不会返还预算。空采样槽、原有规则忽略的
零值/非有限/负时序值不生成事件；其字节仍占源预算。头部声明事件数、音符数和小节数不能证明实际量。
原有每难度 200 万 block 和小节索引范围限制继续保留。

原生 osu 解码器不提供 OJN 二进制解析及这项专用事件政策。缓冲继续使用 .NET Stream、
MemoryStream 和 ArrayPool；只有有界复制循环和集合追加前计数属于自定义适配，不新增原生补丁。
内部可注入小预算用于定向验证；没有新增设置项或改变格式版本。

## 读取与兼容行为

- byte[] 在解密、图片复制和事件构建之前检查长度；此前由调用者分配的数组不在本入口控制范围内。
- 有长度的流在缓冲或所选难度头读取前检查；未知长度流按块计数，只允许多读一个字节确认超限，越限字节不写入缓冲。
- 普通 seek ReadChart 仍直接解析头部和所选难度，跳过另外两个难度和内嵌图片，不先扫描、Hash 或复制全文件。
- ReadChart 使用 .NET ReadAtLeast 读满三字节加密前缀，再重置位置供后续解析；每次返回 1/2 字节的合法流不会误判。EOF 不足三字节仍由后续头解析拒绝，完整前缀但加密/解密头不完整也失败；不关闭调用者流。正常一次读满时不新增前缀读取轮次。
- non-seek ReadChart 必须缓冲一次以支持 OJN 偏移；普通文件直接使用该缓冲，不新增完整数组副本。加密文件复用这份缓冲生成解密输入，减少原来的重复缓冲。
- Read(Stream) 保留从调用者当前位置读取的语义；ReadChart 保留从流起点解析的语义。调用者的输入流不被关闭，临时缓冲和打开的源文件在失败后释放。
- 元数据编码、可选图片容忍、原始引用 0 的空槽语义、合法归一化采样 ID 0、缺失采样不借用和 LN 配对行为保持。OJM/OMC/M30 完整歌曲音频不套用 OJN 或回放上限。
- 缓存命中不进入 Reader；首次/失效解析执行预算。现有 cache 异常移除/重试逻辑保持。
- 已存超限 OJN 可能无法预览、游玩或补算星级；成绩、回放和存储文件保留，不自动迁移、截断或删除。

## 导入与存储边界

源指纹扫描仍只做原有一次 SHA-256；长度检查复用已打开 FileStream，Windows FileShare.Read
保持原有写入/替换保护。快照、导入准备、内容 guard 的 Hash 次数和校验范围不增加。
已有计划仍在原有批次冻结遍历中检查，超限时不进入文件预留/模型事务。

扫描或准备的单个源超过预算，沿现有失败回调计为失败，其他源继续；本轮存在失败时沿用
既有缺失源清理保护，不把未能读取当成源文件已消失。原生存储的补算源超限同样失败，
不发布星级结果。UI 复用现有本地化失败计数，具体异常/失败回调区分 source byte budget 与
materialised event budget，不将其记为无可玩音符或静默成功。

没有新增 Realm 查询、事务、schema、谱面 Hash 公式、导入按键、进度轮次或解码版本。
没有在游玩逐帧、KS 调度、暂停、seek 或模式切换时插入额外文件扫描。
