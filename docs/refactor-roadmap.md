## 原则与完成条件

- 明确的用户玩法契约优先；可靠原版证据用于其余规则，不能把资源名当作完整行为。
- Core 只持有 O2Jam 规则/状态，Formats 只解码，Integration 翻译，Host 承接原生生命周期，Presentation 只消费数据。
- 满足要求时直接使用原生实现；适配必须说明具体缺口、范围、失效行为及升级验证。
- Mania Score 是并列原生路线，不把 Mania 的计分/失败政策塞进 O2Jam Core。
- 分层目录不等于程序集解耦；六条精确接缝例外和两个 partial 仍由语义检查约束。
- 成绩/谱面身份及正式 v5 保持；重构前无标记 replay 是测试实现，不兼容。
- 自动验证、实际运行和用户验收分别记录；测试显式过滤，benchmark 必须先获授权。

## 建议的逐项解决顺序

当前未自动开启新的实现。之后由用户选择具体项；恢复时优先依据 A02/A11 的宿主风险、
A04 的完整客户端矩阵与性能证据、A16 的上游 API 兼容边界，范围各自独立确认。
暂缓功能不会因为这张表存在而重新排入必做项。性能实验历史和版本口径仅在
[存储契约](library-persistence-contract.md)维护，不在路线图复制旧“下一步”指令。
