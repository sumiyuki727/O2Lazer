## 需要修复的具体缺口

以下保留原缺口和设计依据；当前实现状态以本页后续源码合入记录为准。

[OjmReader.ReadLazy](../O2Jam.Formats/Ojm/OjmReader.cs) 保存采样偏移、长度和解密状态，
关闭索引文件后，首次载荷读取重新打开原路径。索引之后改写或替换文件，可能让已加载
采样保留旧字节、未加载采样返回新字节。[OjmArchiveCache](../osu.Game.Rulesets.O2Lazer/Integration/Formats/Ojm/OjmArchiveCache.cs)
的属性检查发生在取得缓存时，无法保护已经交出的 Lazy；不能只修改缓存命中条件。

另一个恢复缺口是：索引 Task 成功不等于其所有延迟载荷都可用。载荷 Lazy 缓存异常后，
原缓存只观察索引 Lazy，不知道载荷已失效；文件恢复到原长度/时间戳时，可能重新取得
同一个已经故障的 archive。仅抛异常、没有归档级失效状态和下一次选择的重建路径不够。

资源保护独立于身份：Read/ReadIndex 的 non-seek CopyTo 无输入上限；实际载荷、WAV
容器和拥有权副本需要在分配前有界。现有 384 MiB 缓存估算、12 项容量及四个准备工作槽
不构成整个进程或原生解码器的硬内存上限；旧消费者可继续持有资源。

## 不改变的边界

- 复用原生 SampleStore/TrackStore、暂停/Seek/变速、音量和播放资源租约；不更换解码器。
- 保留实际采样 ID 0、空槽与缺失采样不借用下一项；M30 的首个合法重复 ID 优先、
  codec 0/5 映射、计数夸大/末项截断容忍、nami/0412 解密及 OMC 跨项加密状态。
- 保留完整延迟索引、跨难度缓存、十秒预取、有界并发/紧急优先、512 KiB 自动采样分流。
- 不在音频更新、readiness 轮询或每次已缓存采样播放中加文件查询，不整体预解码音频包。
- 不新增按钮、Realm 字段、Mod、Core 规则、回放格式或全文件 Hash。
- 预览首音、切换与播放中非谱面空白不能退化；后台执行或操作计数不能替代此项验收。

## R02 候选比较

| 方案 | 可以提供的保护 | 代价与结论 |
|---|---|---|
| 仅依靠已有外层 FileSnapshot | 下次取得缓存时发现通常的文件变化 | 已交出的 Lazy 仍会读新路径，不能单独修复 R02。 |
| 读取当前已打开句柄的属性 | 首次载荷使用与索引一致的长度/最后写入时间；检测到变化后失效 | 不增加打开次数或内容扫描，但增加属性查询；进入隔离候选，性能未验收，暂不合入。 |
| 长期保留 Read/Delete 句柄 | Windows 删除后替换路径时，可继续读旧文件对象 | 实测阻止原地写入；需要归档所有权/租约/驱逐/并行读取的额外设计。不以省查询为由默认采用。 |
| FileSystemWatcher | 通知到达后标记相关缓存失效 | 事件到达前和缓冲溢出仍有窗口，不能独立承担读取一致性。只可作为辅助失效来源，本轮不引入。 |
| 全包 Hash、复制快照或完整预解码 | 可增强内容版本识别/冻结 | 增加整包扫描、磁盘/内存和冷启动工作，与当前性能边界冲突，排除。 |

.NET 8 已提供[基于 SafeFileHandle 的最后写入时间查询](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.getlastwritetimeutc?view=net-8.0)，
无需新的平台 P/Invoke。它仍执行元数据工作，不能称为零成本；时间戳受文件系统更新规则
影响，不是强内容身份。FileSystemWatcher 的[官方错误说明](https://learn.microsoft.com/en-us/dotnet/api/system.io.filesystemwatcher.error)
包括缓冲溢出，也不能据监听器存在宣称事件不会丢失。

## 隔离候选的具体路径

1. Formats 在原索引打开操作中绑定规范绝对路径，并在同一句柄上捕获 Length/LastWriteTimeUtc。
   索引结束后再核对一次。路径规范化不产生额外文件打开。
2. 未物化采样第一次读取时，沿现有 FileStream.Open 路径核对同一组属性；核对成功才分配
   载荷数组。ReadExactly 后再核对，保持所有平台使用同一个明示政策，不依赖 Windows
   共享模式来省掉读后检查。两次属性快照各包含 Length 与 LastWriteTimeUtc，计数不是
   操作系统调用次数；FileStream 可能缓存长度，也不能据此声称没有系统调用成本。
3. 变化或读取 I/O/权限失败使该归档的源状态单向失效。其他尚未加载的采样拒绝继续读取；
   已加载旧字节保持不可变，不把在途旧声音突然切成新版。没有逐帧热重载。
4. OjmArchive 提供廉价内存失效标记（候选名 `IsSourceInvalidated`），不查询磁盘。
   Integration 的 Get/IsCurrentArchive 使用此标记拒绝复用故障 archive；下次选择或
   显式刷新按原流程建立新索引。失败 Lazy 不原地复位，不绕过音频租约重建正在播放的声道。
5. 新索引/新皮肤重新准备载荷；源仍不可用时沿现有失败/缺失处理，其他谱面继续可用。
   原生音频准备和日志由 Host 负责，Formats 不引用 osu、不决定通知或歌曲切换。

同长度、同最后写入时间的改写无法用这组属性判断；保持已有显式刷新边界。
候选测试专门记录了这一限制，而没有把它记成强文件身份已解决。故障标记仅表示已观察
到不再可信/可读，不意味着未标记的文件已经过完整内容验证。目录改名、链接别名、外部
程序绕过共享规则与原生设备等完整平台组合未验收。

### 凭据和版本

每目录拟保存一份记录：缓存格式版本、识别政策版本、规范目录路径、目录时间戳、
全部顶层 OJN 名称的数量/清单摘要、按现行等距规则选出的最多 96 份文件名/长度/
完整 UTC 写入 ticks、识别结果及是否完整取得可复用证据。只存摘要/选样属性，
不保存全库名称数组、源字节、音符、音频载荷或原生模型。

清单摘要复用 .NET SHA-256，以长度前缀编码字段，避免拼接歧义；它是属性摘要，
不是 OJN 内容 Hash。目录键使用规范路径，不因文件同名/源内容相同就跨目录复用。
缓存格式版本仅控制 JSON 形状；政策版本覆盖采样、阈值及字段/头部推断规则，
政策改变必须失效。两者都不替代 ProjectionVersion、身份版本或 Mania 算法版本。

目录 mtime 只能作为附加提示。新增/删除/重命名可能改变等距选样，即使文件不在
旧 96 份中也需失效；参与投票文件的正常原地编辑要靠其长度/ticks 检测。未被
选样且未改变清单的文件内容不参与现行投票，不为其增加头部读取。

现有 `encoding-context:1:none` 表示 Reader 没请求目录回退；枚举 `Automatic`
表示确实请求过但目录没有明确决定；缓存未知/读取失败是第三种状态。不能混淆。
稳定的混合/小目录得到 Automatic 可以复用，但仍执行 Reader 原有同头部/逐字段
推断；因 I/O 缺失部分选样的结果不持久化为稳定决定，临时失败不压住后续正常识别。

### 选曲、文档及资源缓存链

1. 保持 Lazy 回退。ASCII、UTF-8 BOM 或充分字段证据的首次读取不主动访问目录；
   从未请求回退的文档命中也不额外扫描。字段强证据始终优先于目录决定。
2. 对需要回退的读取/文档命中，以当前真实清单重新选样并核对凭据。持久命中只
   打开一份小缓存，不再打开 96 个头部。记录中的文件名只参与比较，实际 I/O
   路径由调用者当前目录生成，不把缓存路径当作任意文件打开指令。
3. miss 沿同一份清单执行现有识别，前后核对清单/选样属性；不稳定结果不可发布
   为可复用记录。读取/识别/解析在锁外完成，不在缓存锁中等待 Lazy 或文件操作。
4. 文档有效身份包含源戳、难度、政策和所用上下文。可以保留现有源键，在返回前
   验证捕获的上下文；不能只在 miss 检查。发布检查代次，旧在途 Lazy/缓存加载
   或保存不得复活已失效结果；最多重新获取一次，持续变化则退出而不无限重试。
5. 旧文档失效同时阻止旧 WorkingBeatmap wrapper 被新选择复用；只改文档键仍
   可能返回旧 Lazy 和 OJM 路径。复用检查移出 wrapper 锁，避免磁盘工作占锁。
6. 不在 Update、音频回调或每次 KS 播放中扫描；不热替换已发声采样。新选择/
   资源重建接收新上下文，变化时拒绝旧音轨转交，继续原生生命周期；KS 映射、
   补播、暂停和时钟政策不变。

### 失效与恢复

| 事件 | 拟定处理 |
|---|---|
| 重启，有效缓存与当前清单/选样属性及政策相同 | 需要回退时加载一份并复用；不预读全库。 |
| 未初始化、缓存缺失/损坏/超限或未知版本 | miss，沿用现行识别；不删除可玩源或改曲库记录。 |
| 目录新增/删除/重命名或采样文件普通原地编辑 | 凭据变化，重识别；旧文档/资源代次不服务新选择。 |
| 当前 OJN 普通改写 | 现行源缓存失效，字段重新解码；它参与选样时目录凭据也变化。 |
| 源搬家/目录重命名 | 新目录键重新识别/核对；成绩身份仍按现行刷新契约处理。 |
| 显式更新谱面 | 保留 Shared.Clear 强制重识别，不能立即从磁盘载回旧决定。仅新完成的识别可生成新凭据。 |
| 原地同长度且恢复 ticks，或路径目标更换后属性相同 | 属性不能证明变更，保留现行热路径弱戳限制；显式更新强制读头部并沿现行源 SHA-256 核对。 |
| 清理/升级/释放与在途加载或保存交错 | 代次屏障丢弃旧完成结果；不得用晚保存/重启载入恢复旧有效状态。 |
| 新旧决定相同，仅凭据更新 | 不因此重算有效 Mania 星级，不换谱面/成绩 ID 或 v5 replay。 |

同戳修改必须明确列为限制，不能把清单摘要说成内容校验。若要求不经刷新也检测
任意同戳替换，须另设内容/文件系统证明；watcher 也不是永不丢通知的证明。本轮
不加入 watcher、长期源句柄或自动全库内容扫描，不降低已有显式刷新保障。

显式 Clear 的协议必须覆盖持久态及在途结果，包括重新启动：拟用存储侧失效
代次/记录废弃保证旧文件不能被再次认领。失效落盘失败、晚写和立即关闭的故障
用例属于候选的前置门槛；只增加一个内存计数不算实现了该保证。若不能在不影响
刷新性能/失败语义的前提下做到，持久恢复路径先不启用，不以功能回退掩盖旧值复活。

### 存储范围、成本与实施顺序

拟使用注入 Storage 子目录 `o2lazer/cache/ojn-encoding/v1`。每目录一个摘要文件名，
最多 128 目录，单记录输入/输出最多 256 KiB，选样最多 96；数值、版本、目录键
及重复项严格验证。超过缓存形状只放弃加速，不缩减合法曲库/长路径支持范围。
一个保存工作者，按目录合并且最多 128 份待写；只加载需要的一份，不逐谱面建任务。
清理只处理本命名空间的已验证摘要文件，不枚举/删除用户源或原生 files。

导入现有每目录首次识别可以贡献记录，不新增逐源查询/Realm 事务，不挂到每个
难度 tag 或触发全库投影迁移。保存可延后/暂停，不阻塞提交；其磁盘竞争仍要纳入
导入/预览性能验收，后台执行不是无退化证明。早期未接线时保持现行识别，并在
服务就绪后接收已有完整结果，不能单为缓存再重读所有头部。

| 顺序 | 完成条件 |
|---|---|
| 1. 隔离目录候选 | 普通上下文/凭据、存储接口及失效代次；保留算法，小型临时目录/可控流用例通过。 |

### 已确认的失败政策

用户明确选择：**保持更新谱面可用，暂不启用跨重启恢复**。默认宿主接线固定为
关闭磁盘恢复，不创建缓存目录、不读取旧记录、不排队保存；仍保留会话内上下文
复用和显式刷新失效。因此本轮没有启用持久加速，也没有给玩家新增设置或按键。

这个取舍针对无法完成任何持久写入的情况：若连会话失效标记都不能保存，刷新后
同长度、同时间戳的源无法与旧缓存凭据区别；下次可写时旧记录可能重新被认领。
内存禁用、后台重试或忽略错误不能提供跨重启保障。不能为了可丢弃的缓存阻止
谱面更新，也不能只翻转开关就把下列候选当作全条件安全的生产持久恢复。
未来启用需重新确定该失败政策或更强的源证明，并单独验收。

| 部分 | 隔离候选实现 |

| 宿主生命周期 | 复用已有宿主注入点与 `GameHost.Exited`，同宿主只建一个服务；退出脱离 resolver、取消待写并等待至多一个在途写入。清理完成才写 clean 标记并释放租约；未完成关闭的会话下次需要重新识别。默认接线因恢复关闭而不创建后端。 |
