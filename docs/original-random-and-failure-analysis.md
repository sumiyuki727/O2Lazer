  `AngelO2Jam.exe` 与其相同，不构成第三份证据。

`.artifacts/o2jamo2-OTwo.exe.asm` 与 `.artifacts/o2jamclassic-OTwo.exe.asm`。

还取决于上游是否继续产生回调、场景状态是否变化，以及结算最终读取哪个字段。
以下分别记录入口内已确认的规则与尚未闭合的生命周期；不把一段局部指令推广到
所有单机、房间、任务或教程模式。

## F07：O2JamO2 的特殊随机

### 已确认的变换

1. 读取参数为 1 时建立镜像列映射，参数为 2 / 3 时先生成整局列置换。
   见 `0x52a100–0x52a1ae`；共同洗牌入口为 `0x52bca0`。
2. 读取结束后进入 `0x52c480`，在 `0x52c4c4` 检查参数是否为 3。
   只有 3 执行额外的时间分段重排，2 不执行该变换。
3. 重排单位为 OJN 小节索引。读取器将包头第一个 DWORD 作为小节索引，维护
   最大索引（`0x52a30e–0x52a33c`），并在可演奏事件记录偏移 `+0x10`
   保存当前小节（`0x52ab9c–0x52aba3`）。变换按这个字段遍历，而非逐 note
   随机分配新列（`0x52c982–0x52c989`、`0x52d0e7–0x52d0ee`）。
4. 先建立受保护小节标记。长条头 `0x02000000` 设置列上的活动长条标记，
   长条尾 `0x01000000` 清除它（`0x52ca49–0x52ca90`）；任一列仍有活动
   长条时，当前小节受保护（`0x52cb14–0x52cb35`）。
5. 还有边界邻近保护：比较下一小节边界的整数位置与 note 位置；note 在边界前、
   距离小于 6 tick 时设置保护标记（`0x52c9db–0x52ca2e`）。该边界位置来自
   读取时建立的小节时间表，见 `0x52a365–0x52a3fd`、`0x52a4b0–0x52a549`。
6. 保护区结束后的一个小节也被标记，循环同时跳过该扩展项，避免无限向后扩展
   （`0x52cb59–0x52cba5`）。连续受保护小节使用同一次列置换；非保护小节
   每小节生成新置换（`0x52cc99–0x52ccc1`、`0x52cf46–0x52cf97`）。
7. 移动的是完整事件记录，使用一对一列置换。同一小节/保护区中的和弦共用映射，
   不会因独立随机选列而合并到一个键；KS 和原始时间字段随事件保留。

洗牌函数本身从恒等映射开始，对每个列索引与 `rand() % 列数` 得到的索引交换。
它不是逐步缩小候选范围的 Fisher–Yates；同样叫“随机”并不保证概率分布完全相同。
这里只确认该构建的实现，不要求新项目复用其全局 CRT 随机源。

### 名称、Classic 与种子证据

- O2JamO2 `0x453c7a–0x453c88` 以技能编号索引名称表 `0x5d07d4`：
  2 Mirror、3 Random、4 Panic。读取调用 `0x528554–0x52858c` 分别将其映射为
  参数 1、2、3，闭合 Panic 到额外重排路线的对应。
- Classic `0x571c30` 先建立列映射，七键分支调用 `0x573940`；特殊随机为
  `0x574330`，参数 3 才执行。七键的边界保护 `0x574852–0x5748a5`、活动 LN
  标记 `0x5748af–0x574907`、保护扩展 `0x5749d0–0x574a1c` 与 O2JamO2 一致。
  每小节及保护段分别在 `0x574dda` / `0x57537e` 调用同一洗牌函数。
  两客户端七键 Panic 包含 Classic 七键 SuperRandom 的行为；O2Lazer 按用户后续选择将该算法显示为 **S-Random**，内部仍为 Panic 身份。Classic 的三键分支不在本次范围。
- 两份客户端均使用带种子的 MSVC CRT 随机发生器。O2JamO2 `srand` / `rand`
  位于 `0x56b639` / `0x56b646`，Classic 位于 `0x5f7229` / `0x5f7236`。
  状态按 `state = state * 214013 + 2531011` 做 32 位无符号回绕，输出
  `(state >> 16) & 0x7fff`。七列洗牌依次交换索引 i 与输出 `% 7` 的索引。
- O2JamO2 读取入口在 `0x52a0f0–0x52a0f9` 使用传入参数初始化种子；调用方
  `0x52861b–0x528632` 从状态字段取值并掩码 `0xfff`，本路线为 0–4095。
  Classic `0x571c41–0x571c45` 同样以传入参数初始化。这里确认的是算法有种子，
  未确认玩家可在原版 UI 自填种子，也未追踪状态字段最初由服务器还是本地生成。
- O2JamO2 包位置先整数除法 `192 / eventCount`，再逐槽累加
  （`0x52a7a4–0x52a7b3`、`0x52ac2f–0x52ac3f`）；小节长度取 `floor(fraction * 192 + 0.5)`。
  这份整数位置仅用于随机边界保护，不要求把当前连续判定位置一起量化。

### 已实现的 Random 设置契约

RD 的原生 Mod 设置弹窗以 `SettingSource` + `Bindable<O2JamRandomAlgorithm>` 创建下拉菜单。
保留原生 Seed 控件、图标、排列、分数倍率与不计表现分政策，无新增全局设置或 Harmony 补丁。

| 选项 / 固定设置身份 | 行为 |
|---|---|
| Random / `Native = 0` | 默认；直接调用 Mania Random，旧回放缺少 algorithm 时仍使用这一布局 |
| 退役 O2Jam 普通随机 / `O2Jam = 1` | 保留原版 CRT 序列及七次全范围交换；只为已有设置/回放兼容，常规菜单隐藏 |
| S-Random（原 Panic）/ `Panic = 2` | 先消耗一次整局置换，再按小节/保护段生成置换并与初始映射组合 |
| R-Random / `RRandom = 3` | beatoraja 风格轮转/镜像轮转，共 12 种布局；是用户选择的扩展，并非原版 O2Jam 技能 |
| 隐藏旧逐音符随机 / `SRandom = 4` | 保留 beatoraja 风格逐音符随机与 40 ms 连打保护、长条/和弦；身份不变但不提供菜单入口，详见[随机契约](column-randomisation.md) |

- 三项共用原生 `Seed`。未填时沿用原生 `RNG.Next()` 生成并写回；明确填写 0 也是有效种子。
  O2Lazer 保留 Seed 的完整 int 范围，不把用户输入强行截断到 12 位；填写 0–4095 可覆盖
  已追踪 O2JamO2 读取入口的原始种子范围。各次调用拥有独立随机状态，不干扰其他 Mod。
- 算法和 Seed 使用原生 ModsJson 序列化，正式 v5 回放归档沿用该数据，不增加私有种子字段。
  以上 enum 身份是算法 v1 的持久化契约；未来改变洗牌/保护语义须新增身份并保留旧解读，
  不能在原有身份下悄悄更换算法。Mirror 继续作为独立原生 Mod 组合。
- `Formats/Ojn` 保留 `RawPosition` / `RawEndPosition`，归一化/长条配对不覆盖原始包位置。
  `Integration` 的 `SourcePositions` / `SourceMeasureTickLengths` 是内存侧信息，无 Realm 写入；
  容器克隆和 MS 换成原生物件时转移引用键，Invert 替换物件后清理旧引用。
- 纯 .NET `O2JamColumnRandomizer` 仅处理位置和列；`O2JamRandomBeatmapTransform` 负责
  宿主物件适配，`Host/O2JamModRandom` 负责选择和 Seed。判定 Core、Drawable、音频及
  osu 全局随机数均不承担随机算法。长条整体换列，样本 ID/音量/声像、毫秒时间和判定位置不变。
- 原版没有 Invert；由该 Mod 生成的物件及无 OJN 包信息的人工物件才由现有时序推导小节。
  无法形成正序 raw 小节区间的异常长条也采用这一回退，不改变已正常化的 playable hold。
  事件数超过 192 的包按原版整数步长得到 0；超大 fraction 长度限制在 16 位范围内。
  这些是对原版输入范围之外数据的稳定性扩展，不宣称与原版拒绝/溢出路径等价。

自动验证覆盖原版已知种子向量、完整和弦映射、空小节随机消耗、5/6 tick 边界、保护区
单小节扩展、跨小节 LN、尾邻近保护、分数模式切换后的元数据和音频不变、重开及正式回放
布局还原、旧回放缺省值、原生下拉/Seed 控件、MS/Invert/DT 组合及重叠归一化时间。
原版与 lazer 的实际分段随机游玩仍待用户验收，不能用固定向量替代视觉/音频验收。

## F14：零血处理是多个字段的条件更新

普通计分入口：O2JamO2 `0x5288f0`；Classic `0x570510`。
两者在入口捕获本次判定前的生命，再分别决定更新哪些字段。将生命扣至 0 的
那次判定仍走原先生命大于 0 的路径；下一次判定才进入入口内的零血分支。

下表只描述回调确实进入这些入口后的行为，不代表零血后所有模式仍会调用它们。
O2JamO2 另有房间条件下的提前返回（`0x528917–0x528996`），表中不涵盖该分支。

| 字段 / 行为 | O2JamO2 普通计分分支 | Classic 普通计分分支 |
|---|---|---|
| 原始分数、生命增减 | 判定前生命为 0 时跳过 | 同左 |
| Jam 推进和断连重置 | 判定前生命为 0 时跳过 | 同左 |
| 普通 Combo | COOL/GOOD 仍加一；BAD/MISS 仍重置 | 同左 |
| 最高 Combo | 在后续生命检查之前比较并更新，局部分支允许继续提高 | 位于生命检查之后，零血时跳过 |
| COOL/GOOD/BAD 次数 | 在各自生命检查之前增加 | 位于生命检查之后，零血时跳过 |
| MISS 次数 | 位于生命检查之后，零血时跳过 | 同左 |

关键证据：

- O2JamO2 Combo/最高 Combo：`0x528a78–0x528acd`；生命检查在 `0x528ad2`。
  最高 Combo 写入函数 `0x4fed00` 直接写状态偏移 `+0x212e`，没有额外生命检查。
- Classic Combo：`0x570638–0x570660`；零血跳转在 `0x570667–0x57066d`，
  最高 Combo 的比较及写入位于 `0x570673–0x5706a7`。
- O2JamO2 统计入口分别为 `0x5289b6`、`0x528a1e`、`0x528bb7`、`0x528bf6`；
  Classic 对应分支见 `0x570551`、`0x5705cb`、`0x5707eb`、`0x570836`。

普通 COOL 的连 COOL/药丸处理发生在计分函数之外、之前：O2JamO2
`0x5271dd–0x52723e`，Classic `0x56e4a3–0x56e51e`。发药丸分支还检查
玩家状态值 6；这个状态字段在零血场景处理中也会被写入。
因此不能由计分函数跳过生命/分数更新，就推出药丸及其进度一定以相同方式冻结。
本轮不把状态值 6 的所有含义、进入时刻和各场景适用范围定为完整规则。

### F14 后续追踪

用户结束随机讨论后继续核对 F14，新的场景、药丸前置条件、结果快照与宿主统计
证据集中在[零血与失败对照](zero-life-and-failure-analysis.md)。本节上表仍只描述
计分入口本身；state 6 且剩余药丸大于 0 时，BAD 会跳过该入口，不能据表推定断连。

本轮已通过 RTTI 区分 O2JamO2 的普通游玩、Couple、教程三条零血分支，确认普通
场景房间字段 0 的 EX/NX/HX 分流及声音停止调用。O2JamO2 曲终可再次复制零血后的
统计；Classic 普通零血先报告网络事件，不能仅由客户端证明官方最终退场规则。
修改前原生计分器仍累计全部后续判定次数，Core 冻结最高 Combo/药丸进度；这些局部
差异已经明确，但最终通过语义、运行回调和官方服务器保存边界仍待验收。

原生 NoFail 的计分/恢复生命与原生失败动画是项目接入政策，不能套用到原版无 Mod。
静态检查阶段未修改玩法、通过 36 项基线；用户随后选定新 EX 契约，已实现并通过
145 项过滤验证。原版证据仍不等同于完整实机验收，新规则也仍待客户端确认。

## 未来重新启动时的核对方法

原版阶段已结束；以下仅保留方法，不安排新的原版验证或规则修改。

先闭合调用链和场景字段，再将已确定算法写成无宿主依赖的规则表或伪代码。
必要时用极小人工谱面对指定原版分支进行隔离验证，最后只对尚存歧义做客户端实测。
不需要先靠玩家游玩大量谱面来猜规则，也不能让视觉组件替代状态规则。
