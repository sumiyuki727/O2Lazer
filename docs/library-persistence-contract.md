# A04：曲库与成绩的持久化身份

更新：2026-10-01。前半页记录现有实现和已确认的成绩保留规则，后半页给出 A04 重设计与实施顺序。A04-1 的统一投影/版本及 A04-2 的身份迁移已经实现并在临时库验证；去重/通知及文件预留仍是待实现方案，没有读取或清理客户端真实库。

## 身份与版本现状

| 对象 | 当前写入位置与来源 | 用途及稳定性 |
|---|---|---|
| ruleset | 原生 `RulesetInfo.ShortName = o2lazer` | 区分 O2Lazer 与其他 ruleset；旧程序集版本更新后仍须解析到同一 ruleset。 |
| 源 OJN | `BeatmapSetInfo.Files` 中的 OJN 文件；`RealmFile.Hash` 为源字节 SHA-256 | 内容寻址；不是外部路径，也不是谱面难度身份。 |
| 外部路径 | `BeatmapInfo.Metadata.Source` 存目录，set 文件名存 OJN 文件名 | 查找、刷新、移动检测和缺失标记；路径改变本身不应换谱面 ID。 |
| set | 原生 `BeatmapSetInfo.ID`；`Hash` 为 `SHA256("o2lazer:" + 排序后的难度 MD5)` | 同源可玩难度的集合；旧版 set hash 是排序后 MD5 的直接拼接，迁移时原位更新。 |
| 难度 | 原生 `BeatmapInfo.ID`；`MD5Hash = MD5(源字节 + 难度编号)`；`Hash = SHA256(小写源哈希 + ":" + 难度编号)` | ID 是本地关联键，Hash 是成绩与原生缓存的匹配键。旧版三难度曾共享源文件 SHA-256；同源迁移时原位分开。 |
| 成绩 | 原生 `ScoreInfo.ID`、`BeatmapInfo` 关联与 `BeatmapHash` | `BeatmapHash` 必须与关联谱面的 Hash 一致；旧成绩 ID 和成绩内容不得因谱面元数据重算而替换。 |
| 正式回放 | `ScoreInfo.Files` 与 `ScoreInfo.Hash`，归档内 `ruleset=o2lazer`、schema v5、谱面 Hash/MD5 | v5 是正式契约；重构前无标记测试 replay 不兼容。文件归属和成绩 ID 不能因后端迁移丢失。 |
| 文件夹收藏夹 | 原生 `BeatmapCollection.BeatmapMD5Hashes` | 根据活动谱面和外部目录同步；用户自建收藏夹不归本功能清理。 |

A04-1 使用原生 `BeatmapMetadata.Tags` 承载 `o2lazer-projection:1:20261001`、身份版本 1、独立难度编号及原 Lv；`o2lazer-encoding-context:1:none/0/1/2/3` 区分无需目录回退与实际采用的目录决定。`o2lazer-encoding:2` 继续标记解码策略，`o2lazer-source-size:<字节数>` 辅助刷新；Mania 星级与最大连击保持独立算法版本。`o2lazer-clean:2` 仅保留旧载体兼容，不再证明投影完成。显式刷新会先比较 `LastLocalUpdate` 与源长度，再核对原生文件存储里的源 SHA-256；时间戳和长度相同不能证明内容相同。没有独立的 O2Lazer 数据库 schema 版本；存储仍使用原生模型，没有第二套持久化的源/set/难度表。

## 字段所有权与更新边界

下表区分 OJN 数据、宿主投影和用户数据。A04-1 已让新增和同源刷新共用赋值清单；A04-2 补齐三难度身份、明确成绩关联及 MD5 收藏夹迁移。

| 字段组 | 来源与所有者 | 同一源字节时的更新规则 |
|---|---|---|
| OJN 字节、源 SHA-256、源文件引用 | Formats 解码前的源字节；文件落盘由存储适配器负责 | SHA-256 不变才可原位刷新；改变时创建新 set，旧 set 按原生生命周期清理。 |
| 外部目录、文件名、时间戳、长度 | 用户曲库路径与文件系统；Host 扫描负责 | 搬家或重命名只更新位置及扫描提示，不改变谱面/成绩身份。时间戳和长度只用于筛选，不能替代 SHA-256。 |
| set Hash、难度 MD5/Hash、难度编号 | 导入规划器与 O2Jam 身份算法 | 算法版本迁移须按源字节和 EX/NX/HX 一对一识别旧谱面，保留原 ID；只改当前谱面 Hash 时同步修正原来附着的成绩 Hash。 |
| 歌曲 ID、标题、歌手、谱师、文本编码、封面 | OJN 文档与解码版本 | 解码策略升级后重新投影；封面文件引用由存储适配器更新。不得从旧标签反推 OJN 原值。 |
| 难度名、等级、列数、OD、BPM、长度、物件和长条数量 | OJN 难度、谱面时序与 O2Jam 投影规则 | 投影规则升级后逐字段原位重算；仅更新存在且可证明属于该 EX/NX/HX 的谱面。缺失或新增难度需要单独迁移策略。 |
| Mania 星级和最大连击 | Mania 计算器及其独立版本 | 算法版本变化时重算缓存，不改变 OJN 或成绩身份；等级颜色仍从 O2Jam 等级读取。 |
| 原生本地状态：`DateAdded`、`UserSettings`、`Hidden`、`LastPlayed`、收藏夹 | osu!lazer 与用户 | 不因重新解码或元数据重算覆盖；仅原生用户操作或明确的收藏夹同步规则可修改。 |
| 成绩、正式 v5 replay、成绩 ID/Hash/文件 | 原生 `ScoreInfo` 和回放存储 | 不重新生成成绩内容；源内容变化时保留旧 Hash 且不转挂。只对同一源、同一难度的旧共享 Hash 做一次映射。 |

原生 `BeatmapInfo.UpdateStatisticsFromBeatmap` 使用可玩长度和最常见 BPM；当前 OJN 投影使用声明/末音长度与初始 BPM，直接调用会改变现有曲库数据。原生 `BeatmapInfo.UpdateLocalScores` 仅按 Hash 重挂成绩；旧版三难度共享源 Hash 时，必须先利用已有关联分别迁移，不能用全局 Hash 匹配。文件存储、待删除 set 的清理和成绩记录保留继续复用原生实现。

## 已确定的更新规则

| 输入变化 | 当前行为 | 重构约束 |
|---|---|---|
| 同一源字节，重算标签、星级或编码 | 原位更新 set/难度，并将旧共享 Hash 的已关联成绩改为独立难度 Hash | 保留 set ID、难度 ID、成绩 ID、原生成绩关联；不得将 EX/NX/HX 的成绩串到另一难度。 |
| 源文件搬家，字节不变 | 刷新服务按长度和 SHA-256 找到旧 set，更新外部路径 | 保留原 IDs 和成绩；重复副本只保留一个活动 set。 |
| 同一路径的 OJN 字节改变 | 新建 set/难度，旧 set 标记 `DeletePending`；写入后旧成绩暂时关联旧谱面；下次启动时原生 Realm 清理会移除待删除 set 和谱面对象，成绩记录及旧 `BeatmapHash` 留下 | 用户确认旧成绩不得自动挂到新版谱面。即使只改元数据，当前也按源字节变化处理。历史成绩不会出现在新版谱面排行榜中；用户确认只保留成绩记录和旧 Hash，无需继续打开旧谱面。 |
| 源文件缺失或用户清理 O2Lazer 曲库 | 将本 ruleset 的 set 标记 `DeletePending`，原生启动清理随后移除这些 set 和谱面对象 | 不标记成绩删除；成绩的旧 `BeatmapHash` 保留。用户确认无需在客户端继续打开旧谱面。 |

2026-09-26 的临时 Realm 回归已验证：改动 OJN 的一处可玩物件并恢复原时间戳后，即使文件长度也不变，显式刷新仍会创建不同 ID/Hash 的新谱面；旧 set 待删除，同一会话内旧成绩的 ID、连击和旧谱面关联保持不变，新谱面没有继承成绩。临时库模拟重启还验证了原生 `RealmAccess` 清理会移除旧 set/谱面，成绩 ID、连击和旧 `BeatmapHash` 仍在，`ScoreInfo.BeatmapInfo` 变为 null。2026-10-01 A04-2 补上三难度、搬家/改名、集合与歧义保护证据；重复副本竞争与文件失败回滚继续归后续步骤。

## 写入重设计前必须解决的缺口

1. **字段投影与版本（A04-1 已落实）**：新增/刷新共用字段赋值及媒体引用同步，版本与字段在同一模型事务提交；源快照及版本编解码归 Host/Library，Realm 类型仍只在存储适配器。原 Lv、槽位、目录回退决定单独存储；未知未来版本、重复 token 或槽位冲突不覆盖。A04-2 已补齐三槽位/MD5，文件恢复与实机验收继续按后续步骤处理。
2. **身份判定（A04-2 已落实）**：旧版共用源 Hash、新版按难度 Hash、set hash 改版、原生 `BeatmapInfo.ID` 和 `ScoreInfo.BeatmapHash` 一同映射。仅凭路径、标签或一个 MD5 不迁移。规划器提供三槽位身份，活动投影只保留可玩难度；用户确认的旧空槽位保留成绩/历史 Hash、移除谱面关联已在临时库验证。
3. **刷新与重复**：显式刷新现已核对 OJN 源 SHA-256，时间戳和长度不变也可发现内容修改；这会增加一次顺序读取，仍须在大曲库实测扫描成本。已导入的 OJN 即使跳过写入，刷新结束也会撤销其 OJM 播放缓存，让下次选曲重读归档；OJM 内容不进入谱面身份 Hash，正在播放的曲目不热替换。相同内容的搬家与同时存在的副本走不同分支，重复副本竞争仍需验证。
4. **事务与文件**：`WriteBatch` 的 Realm 模型更改共用一笔事务，但原生 `RealmFileStore.Add` 在事务内把字节写入磁盘；数据库回滚不等于文件系统回滚。新后端需要为文件暂存、失败重试、孤儿文件回收定义边界。
5. **后端替换**：当前 `IO2JamLibraryWriter` 表示导入动作，不是数据模型或迁移协议。先形成源、set、难度、成绩和文件的后端中立身份/版本表，再在临时数据库验证更新、移动、重复、缺失和失败重试；不直接对用户库试迁移。

## 重设计草案的范围与分层

字段、身份、版本和恢复协议已形成设计，A04-1/2 已落地，其余继续分小步实现。继续使用宿主原生 Realm/文件库/成绩模型，不建立第二份成绩库，不预先实现 SQL 或本地/服务器档案。旧元数据只作为证明身份、原 ID 和用户状态的迁移输入；可重算字段重新从 OJN 投影，不继承旧实现的错误值。重构前测试 replay 不兼容，正式 v5 文件及已存成绩保持契约。

| 所有者 | 重设计后的责任 | 保留的边界 |
|---|---|---|
| Formats | OJN/OJM 解码结果 | 不认识导入版本、Realm、Mod、UI 或用户库 |
| Integration | 格式到运行谱面/采样引用的映射 | 不决定成绩迁移、持久化字段或数据库事务 |
| Host/Library | 源快照、导入投影、原生元数据载体编解码、版本比较、身份公式/槽位清单和操作计划 | 数据使用源哈希、难度编号、普通值和不透明 ID；不返回 Realm 托管对象 |
| Host/Difficulty | 无 Mod Mania 缓存与算法版本 | 不把 Lv/10 写入原生 StarRating，不决定 O2Jam 判定 |
| Host/Persistence/Realm | 旧原生模型身份核验/映射、字段赋值、成绩/集合关联、文件预留、事务、原生清理接入 | Realm 类型及具体查询只在适配器；原生模型编译耦合仍存在，不宣称已能直接换 SQL |
| Presentation | Lv 文本/颜色、筛选、标签与设置进度 | 消费已提交数据，不借显示文本决定迁移身份或写入版本 |

沿用并逐步整理 `O2JamImportPlan`、`O2JamImportedSource` 和现有写入契约；不先生成通用 ORM、全新谱面模型或跨 ruleset 存储接口。第二 ruleset 出现实际使用者后再提取公共设施。

## 统一字段投影

A04-1 已让新增和同源刷新消费同一投影，不再各写一份赋值清单。源快照从同一组 OJN 字节得到 SHA-256、解码数据、源长度和文件内容；时间戳/路径作为位置提示一起捕获，不能在写入阶段用后来读取的文件时间给较早字节盖章。提交前发现源已经变化时中止该项并重试；文件系统本身不参与数据库事务，无法保证外部文件永远不变。

| 投影字段 | 写入目标与第一阶段规则 | 当前落实状态 |
|---|---|---|
| 源字节/SHA-256/文件名 | 原生文件库及 set 文件引用；文件哈希使用原生编码，难度 Hash 不作文件主键 | 新增/刷新共用原生文件写入；A04-2 已按内容识别搬家+旧 set Hash，不再要求旧路径相同 |
| SourceDirectory/文件名/源长度/源时间 | Metadata.Source、AudioFile、原生命名文件引用、源长度载体、LastLocalUpdate | 已使用同一快照；提交前验证内容并持有 Windows 只读句柄，不再重读时间为旧字节盖章 |
| SongId、Title、Artist、Author | o2ma 搜索标签、标题/歌手/谱师；继续当前空标题文件名回退和空谱师 O2Jam 回退 | 已写当前源的 o2ma 标识并保留无法证明归属的其他标签；原生作者为 embedded 对象，改名复用原生 DeepClone 以隔离脱管快照共享引用 |
| 难度编号、原 Lv、DifficultyName | 独立的结构化编号/Lv 值，难度名仍为现有英文固定存储格式；展示读原 Lv 后做颜色投影 | 已写独立槽位/Lv，读端优先使用；三槽位清单保留空难度身份，旧记录按唯一内容证据或已知完整存储名称识别 |
| CS/OD 与其他默认难度字段 | CS=7，OD=clamp(Lv,0,10)，其余继续现有原生默认值；这是宿主元数据，不是 Core 判定或 MS 的 OD/HP 基线 | 已统一重写，难度字段复制复用原生 CopyTo |
| BPM | 保留当前初始 BPM 规则 | 已刷新初始 BPM；直接调用原生统计会改变该口径 |
| Length | 保留当前 max(OJN 声明长度，解码音符/音频事件末位置换算时间+5000ms)，不把 BPM 事件当作末音 | 已统一刷新；保留现有统计口径 |
| TotalObjectCount/EndTimeObjectCount | 可演奏物件数/其中长条数，与现有规划器一致 | 已统一刷新 |
| 封面/缩略图回退 | 沿用 cover 优先、thumbnail 回退，更新文件引用和 Metadata.BackgroundFile；移除不再使用的自有命名引用，不直接删全局文件 | 已同步封面引用，释放废弃自有命名引用，保留原生全局文件及其其他引用 |
| Mania 星级/最大连击 | 无 Mod 基线写 StarRating，最大连击写现有缓存载体；继续原生 Mania 计算与当前适配版本 | 已与版本一起提交；同源且算法版本有效时，文本/投影更新复用缓存 |
| 系统标签与投影版本 | 只替换已登记的 O2Lazer 自有前缀及确定属于本源的 o2ma 标识 | 已用独立投影版本；全组难度校验，不再以 clean 标记证明完成 |
| 原生用户状态与额外字段 | 保留 set/难度 ID、DateAdded、UserSettings、Hidden、LastPlayed、BeatDivisor、用户标签及非导入拥有字段 | 原 ID/状态对象不替换，非自有标签、Unicode/在线字段不覆盖；临时库验证成绩与用户收藏夹保持 |
| 成绩/replay/收藏夹 | 仅按下节的已证明身份映射调整关联；成绩值、ID、文件及回放帧不重生成 | A04-2 临时库已验证三难度、未关联共享 Hash、空槽位、用户集合及正式 v5 唯一匹配；完整客户端流程仍归 A04-5 |

OJN 不提供独立的罗马字/Unicode 双份信息；第一阶段不新增自动转写策略，也不顺带重置已有 Unicode 或在线字段。其他元数据更新口径有新需求时另定版本和验收。读取投影的失败/冲突结果须使用现有本地化系统显示，不能在 Realm 写入器内组装产品文案。

## 版本设计

原生数据库 schema 版本属于 osu!，本 ruleset 不读取它来判断自身元数据是否更新，也不修改它。O2Lazer 的版本描述投影/缓存含义，不描述 Realm 的物理表结构。

| 版本 | 当前规则/后续约束 | 触发的工作 |
|---|---|---|
| 投影载体格式 | 整数，从 1 起；解析字段结构发生不兼容变化才更新 | 选择适配器解析方式；未知更高格式不覆盖、不当成旧版自动降级 |
| 元数据投影算法 | 原生难度算法同类的单调整数，当前为固定值 20261001；更新含义时明确递增，运行时不生成时间版本 | 同源字节的难度名、等级、统计、来源和媒体引用重算，不改变规范内容身份 |
| 文本解码策略 | 保留现有 encoding:2 的迁移语义，之后由解码接入策略独立递增 | 文本重投影；不触发新成绩身份 |
| 身份算法 | 当前源 SHA-256、难度 Hash/MD5 和 set Hash 规则冻结为版本 1 | 只有未来明确更改身份公式时才制定专门迁移；不随投影算法版本一起变 |
| Mania 缓存 | 继续使用原生 Mania Version 与现有 CacheVersion=Version*10+2 | 重算星级/最大连击，不替代投影版本 |
| replay | 正式 schema v5 保持不变 | 导入/读取验证；与上述元数据版本分开 |

Realm 原生模型不能随意增加持久化字段，A04-1 已将投影版本、身份版本、难度编号及原 Lv 写为登记的 Tags token： `o2lazer-projection:1:20261001`、`o2lazer-identity:1`、`o2lazer-chart:1:0`、`o2lazer-level:1:75`。Tags 编解码位于 Host/Library 的原生元数据桥，供写入和显示读端共用，不依赖 Realm 类型；它是宿主投影载体，不是后端中立契约本身。既有编码/Mania token 继续由各自策略管理，未来后端可使用独立列，发布原生 BeatmapInfo 时再投影为宿主载体。

目录编码回退也是可变的解码输入。同一源字节和相同策略版本不保证目录上下文从未变化；准备投影时需要明确编码决定及是否依赖目录回退，对依赖上下文的旧文本在显式刷新时重验。不要把 encoding:2 单独当作所有文本无需重新检查的证明，也不要因重验文本就无条件重跑 Mania 计算。

读端先验证格式、版本、唯一 token、数值范围及源/槽位身份；同前缀重复或互相冲突不能取第一个就盖章。没有新标记的旧记录进入最小身份识别路径，不能直接认为已更新。标记只有在该难度全部应更新字段和缓存成功提交后写入；源级“已是当前版本”必须核对所有活动难度，不能只看某个难度的标签。旧 clean 标签只作兼容输入，不再用它证明新投影完成。

## 身份匹配与迁移规则

1. **验证所有者与内容**：规则集必须为 o2lazer，源身份从已存 OJN 文件引用/可验证旧记录得到。只靠路径或 set Hash 不足以证明同源；已知 set ID 也是查询提示，不是内容证明。混有其他 ruleset 难度的 set 不作为可整组改 Hash/标记删除的对象，先保留并报告冲突。
2. **识别槽位**：优先使用验证后的独立难度编号与源身份，其次使用源字节计算的规范 Hash/MD5。仅在有内容证据、已知旧写入格式且恰好唯一对应时允许旧名称回退；证据冲突、无候选或多候选保留原记录，不写“当前版本”。准备迁移时读取全部三槽位身份与可玩性，活动投影仍只包含可玩难度，不复制第二份音符模型。
3. **同源更新**：保留 set/难度 IDs、用户状态，统一重投影；搬家/改名与旧 set Hash 版本变化同时发生也复用这些 IDs。A04-2 已解除内容匹配的同路径门槛；同一个内容有多个旧 set 时拒绝自动选取。登记路径经内容验证仍可用时保留；原路径已证明缺失或可读内容已经改变后，才更新到同内容副本。
4. **旧共享 Hash 成绩**：在改变难度 Hash 前快照原有明确关联，按已经证明的 EX/NX/HX 分别修正这些成绩的 BeatmapHash/关联。保持成绩 ID、分数、统计、Mods、日期、Rank 与文件。没有明确难度证据的未关联旧成绩保留旧 Hash，不在全库按共享 Hash 批量重挂。三个难度的映射须在同一模型事务完成。
5. **可玩槽位变化**：同源出现新增可玩难度才创建该难度的新 ID；已唯一识别、如今不可玩的旧槽位保留其成绩记录和历史 Hash，按原生模型生命周期移除相应谱面关联。用户已确认该规则，A04-2 已实现并验证。未知槽位不推断成某个难度，也不自动清除；该 set 暂不更新并报告冲突。完全无可玩内容/解码失败时保留现有条目并报告，不能当作成功刷新。
6. **MD5 与收藏夹**：同源且槽位已确认才更新旧 MD5。旧 MD5 在库中唯一对应目标难度时复用原生 `TransferCollectionReferences`；多个难度或多个 ruleset 共用旧 MD5 时保留原集合引用并报告，不全局替换、不猜测用户想收藏哪个对象。自动文件夹收藏夹再走现有同步，不能删除用户集合。
7. **正式 v5 文件**：当前规范 Hash/MD5 公式不变，元数据版本更新不改归档字节。已经关联的成绩继续按原生记录读取回放；独立重新导入按 o2lazer 身份与 Hash/MD5 的唯一一致匹配，不能先按共享 Hash 任取一个就忽略 MD5。旧共享 Hash 可用有效独立 MD5 消歧；二者冲突或都无法唯一定位时明确不自动关联。未来若真要改规范身份算法，须另定归档身份映射与回归，本方案不预建 alias 数据库。
8. **内容改变/明确缺失**：沿用已确认政策——创建新内容身份后，旧成绩保留为历史，不挂新版；旧谱面对象最终可由原生清理。访问失败、不可达磁盘、解码失败或取消不是已证明缺失，不标记删除；不能把 `File.Exists=false` 单独当作整个扫描成功的证据。

新记录与旧记录都不依赖 Lv 颜色、显示难度名或当前 UI 语言来产生身份。身份不能由最终星数、成绩或文件夹名计算。

### A04-2 实施边界

规划器在 Host/Library 中提供全部 EX/NX/HX 的 MD5 和可玩性清单；活动字段投影仍只含可玩难度，没有复制音符模型。规范 set Hash、MD5 与难度 Hash 公式集中在 `O2JamBeatmapIdentity`，公式和身份版本 1 不变。已写当前标记的难度也要在显式刷新时用稳定源快照核对 MD5；set Hash 同时核对完整可玩成员集合，避免缺少槽位的记录被当成无需更新。

Realm 适配器先验证整组所有者、版本、源内容及槽位证据，再快照明确成绩关联和全库旧 MD5 所有者。按同一模型事务改难度 Hash/MD5、成绩关联、字段及集合；集合唯一性按大小写无关比较并在更改任何难度前确定，避免前一个更新改变后一个的证据。集合无歧义时调用原生 `TransferCollectionReferences`，有歧义则保留集合原引用并记日志。不可玩槽位先解除成绩关联，再按原生清理方式移除其 Metadata/BeatmapInfo，不删除成绩或共享文件。

正式 v5 导入使用原生导入器现有 Realm 接缝查询活动 O2Lazer 难度，要求 Hash/MD5 的唯一一致匹配；验证过的旧源 SHA-256 可以结合独立 MD5 消歧。原生 `QueryBeatmap` 只返回第一个匹配，不能满足该要求，因此此查询仍在 Realm 适配器。归档编码和字节不改，已存成绩按原记录加载其回放。独立旧归档若含非规范且已被修正的旧 MD5，不建立别名表猜测目标，按无法匹配处理；已存文件的读取不依赖重新匹配这些归档字段。

缺失证明来自可完整读取的父目录或祖先目录：某个路径段明确不存在才允许清理。目录存在但不可遍历、根磁盘不可达或读取异常均不等于缺失；扫描不完整、解码失败或取消不执行缺失清理。扫描器不再忽略无法访问的目录。提交删除标记前还会重查 set 当前路径，避免旧扫描索引删除刚搬迁成功的记录。

A04-2 的证据为 20 项临时库迁移及 21 项正式回放导入测试，包括三难度+旧 set Hash+搬家/改名、不同成绩及回放文件保留、未关联共享 Hash、唯一/跨 ruleset/跨难度 MD5、空槽位移除和缺失槽位补建、身份冲突/混合 set/重复 set 拒绝及缺失保护。这些证据没有覆盖真实库写入；文件事务失败恢复和更完整的取消/通知行为继续按下面的实施步骤完成。

## 重复副本与操作顺序

扫描与准备按规范源 SHA-256 归组；当前会话的批内结果也更新索引，不能只使用刷新开始前的旧快照。相同内容的新路径不重复创建活动 set/难度；已登记路径必须通过内容验证才优先保留，原路径明确缺失或可读内容改变后迁往成功验证的副本。路径以完整路径的 OrdinalIgnoreCase、Ordinal 次序排序，并去掉同一路径的重复输入；不依赖目录枚举或并行任务完成顺序。

已有多个旧 set 时，不自动合并成绩、挑一个覆盖用户设置或删除其余记录。先检查逐难度身份和关联，作为迁移冲突保留；后续如需归并须单独明确规则。普通副本去重与旧库归并是不同操作。

一次有界批次分为：读取稳定源快照 → 解码/计算投影 → 准备身份与更新计划 → 核对当前数据库状态 → 文件预留 → 模型事务 → 提交后通知。事务开始时须重查所有者、内容、版本和已删除状态，不能只信任工作线程较早的快照。编码/计算失败不进入写入阶段，扫描不完整不做缺失清理。

取消只阻止尚未提交的批次；已提交批次保留，并完成缓存失效。提交后的监听器/缓存通知失败不等于数据库回滚，应单独诊断和重试通知，不能把已提交结果当成未写入。通知只发生在模型事务提交后，不随文件预留事务发生。

### A04-3 实施边界

Host/Library 在扫描中仅保留 SHA-256 指纹，不保留整库源字节；先按内容归组，再以两个工作线程准备每批最多八个唯一源。旧索引即使缺少源长度，也参与按 SHA-256 查找。已登记路径可读且仍含同一内容时保持原路径，包括它不在本次输入范围的情况；不可访问时保留并报错，不把读取失败视作缺失。内容已改变而有可靠旧副本时，先迁移旧内容，再把原路径的新内容导入为独立身份，保留旧成绩与难度 ID。

Realm 适配器在每个模型事务内建立 O2Lazer 活动集合的路径/源内容/set Hash 索引，并即时重新登记被更新、新建或标记删除的集合。删除了只信任扫描期 `SourceIndexWasLoaded` 的分支；已知 ID 仍只是提示，不能覆盖当前路径的不同所有者。原生没有外部 OJN 的批内内容/路径协调入口，因此索引是此适配器的局部实现，不暴露 Realm 对象到 Host/Library。源快照及替换前仍可读的登记源保持只读句柄直到提交。

旧重复集合继续拒绝自动归并；副本目标被另一套旧谱面占用，包括两条登记路径互换内容，保留两套数据并作为冲突报告。本阶段不自动交换这些路径或合并用户状态。扫描、解码或模型写入失败时不执行缺失清理；模型事务失败会计入这一批的未写入项，后续独立批次可继续。

提交后每个原生工作谱面/难度缓存监听器独立执行，源文件缓存也独立通知。通知队列只在内存保留每个对象/接收方的最新失败值；成功接收方不因另一方失败被重发，解除订阅的接收方不会重试。下次显式刷新重试，宿主重启仍走原生缓存重建，不增加永久 outbox、后台重试或存储 schema。通知失败记为 PendingNotifications，已提交 Imported/Updated 与 Failed 计数分开。

取消发生在提交后时，先统计整批结果并完成通知尝试，再以带结果快照的 O2JamImportCancelledException 停止后续批次；应用会话不丢失这一快照，设置页复用原生取消通知显示已导入/更新数量。提交后集合同步失败同样保留写入结果，下一次刷新可重试。新增提示使用中英资源；没有自定义进度控件或新补丁。

A04-3 的自动化基线为 968 项过滤回归（Formats 41、Core 55、检查器 15、宿主常规 804、临时旧库迁移 32、正式 replay 导入 21），全部源码和语义分层检查通过。临时 Realm 夹具单独运行；没有部署客户端、操作真实旧库或运行 benchmark。文件落盘恢复仍须 A04-4 验证，完整实际游玩/媒体/回放链路留到 A04-5。
## 文件预留与失败恢复

原生 `RealmFileStore.Add` 已按内容哈希去重、校验旧文件，并通过 `Storage.CreateFileSafely` 写入，继续复用。具体缺口是文件落盘不能被 Realm 事务撤销：如果新的 RealmFile 行也随模型事务回滚，原生 `Cleanup()` 仅查询数据库内零引用行，无法发现这个未登记磁盘文件。

建议在 Realm 适配器中采用两个模型事务，不添加自有数据库 schema 或文件系统清理器：

1. **预留事务**：从已验证源/背景快照计算原生文件 Hash，查询并为缺少的 Hash 添加原生 RealmFile 行，提交后仍无命名引用。既有文件行及其他 ruleset 引用原样保留；本阶段没有谱面/成绩更改或刷新通知，也不写入文件字节。
2. **谱面事务**：确认预留行仍存在，再调用原生 `RealmFileStore.Add` 校验/安全写入文件，应用所有字段、成绩/收藏夹关联和命名引用，最后提交。同一数据库事务锁内原生清理不能同时移除预留行；如果开始前预留丢失则停止并重新准备，不能直接退回未预留写入。
3. **失败与重启**：模型事务失败时旧谱面/成绩保持原样；新预留行仍在且 Usages 为零。重试可按同一 Hash 复用已写文件，宿主下次启动的原生清理可回收零引用行及文件。若文件原本被其他对象使用，不得删除或降低其已有引用。

它提供模型事务原子性和可追踪文件恢复，不承诺数据库与文件系统共同原子提交。需要测试预留后取消、文件写入异常、第二条请求失败、提交前失败、重启清理及共享文件保护；在这些验证通过前不能部署到真实库。过去已经落盘但没有 RealmFile 行的孤儿不在自动回收范围，不全局扫描/删除原生文件库。

未来宿主后端改变时保留“先有可追踪记录，再发布引用”的恢复语义，按新原生文件库实现，不移植 Realm 具体类型或假定 SQL API。
