# A04：曲库与成绩的持久化身份

更新：2026-10-01。前半页记录现有实现和已确认的成绩保留规则，后半页给出 A04 重设计草案与实施顺序。草案尚未实现或完成迁移验收；本轮仅检查本仓库及只读原生源码，没有读取或清理客户端真实库。

## 身份与版本现状

| 对象 | 当前写入位置与来源 | 用途及稳定性 |
|---|---|---|
| ruleset | 原生 `RulesetInfo.ShortName = o2lazer` | 区分 O2Lazer 与其他 ruleset；旧程序集版本更新后仍须解析到同一 ruleset。 |
| 源 OJN | `BeatmapSetInfo.Files` 中的 OJN 文件；`RealmFile.Hash` 为源字节 SHA-256 | 内容寻址；不是外部路径，也不是谱面难度身份。 |
| 外部路径 | `BeatmapInfo.Metadata.Source` 存目录，set 文件名存 OJN 文件名 | 查找、刷新、移动检测和缺失标记；路径改变本身不应换谱面 ID。 |
| set | 原生 `BeatmapSetInfo.ID`；`Hash` 为 `SHA256("o2lazer:" + 排序后的难度 MD5)` | 同源可玩难度的集合；旧版 set hash 是排序后 MD5 的直接拼接，迁移时原位更新。 |
| 难度 | 原生 `BeatmapInfo.ID`；`MD5Hash = MD5(源字节 + 难度编号)`；`Hash = SHA256(小写源哈希 + ":" + 难度编号)` | ID 是本地关联键，Hash 是成绩与原生缓存的匹配键。旧版三难度曾共享源文件 SHA-256；同源迁移时原位分开。 |
| 成绩 | 原生 `ScoreInfo.ID`、`BeatmapInfo` 关联与 `BeatmapHash` | `BeatmapHash` 必须与关联谱面的 Hash 一致；旧成绩 ID 和成绩内容不得因谱面元数据重算而替换。 |
| 正式回放 | `ScoreInfo.Files` 与 `ScoreInfo.Hash`，归档内 `ruleset=o2lazer`、schema v5、谱面 Hash/MD5 | v5 是正式契约；重构前无标记测试 replay 不兼容。文件归属和成绩 ID 不能因后端迁移丢失。 |
| 文件夹收藏夹 | 原生 `BeatmapCollection.BeatmapMD5Hashes` | 根据活动谱面和外部目录同步；用户自建收藏夹不归本功能清理。 |

元数据版本目前分散在 `BeatmapMetadata.Tags`：`o2lazer-clean:2` 标记导入元数据，`o2lazer-encoding:2` 标记文本解码，`o2lazer-source-size:<字节数>` 辅助刷新；Mania 星级与最大连击另有算法版本标签。显式刷新会先比较 `LastLocalUpdate` 与源长度，再核对原生文件存储里的源 SHA-256；时间戳和长度相同不能证明内容相同。没有独立的 O2Lazer 数据库 schema 版本，也没有后端中立的源/set/难度记录。

## 字段所有权与更新边界

下表是新写入契约的设计输入；它区分 OJN 数据、宿主投影和用户数据。当前 `refreshMetadata` 尚未完整执行这些规则。

| 字段组 | 来源与所有者 | 同一源字节时的更新规则 |
|---|---|---|
| OJN 字节、源 SHA-256、源文件引用 | Formats 解码前的源字节；文件落盘由存储适配器负责 | SHA-256 不变才可原位刷新；改变时创建新 set，旧 set 按原生生命周期清理。 |
| 外部目录、文件名、时间戳、长度 | 用户曲库路径与文件系统；Host 扫描负责 | 搬家或重命名只更新位置及扫描提示，不改变谱面/成绩身份。时间戳和长度只用于筛选，不能替代 SHA-256。 |
| set Hash、难度 MD5/Hash、难度编号 | 导入规划器与 O2Jam 身份算法 | 算法版本迁移须按源字节和 EX/NX/HX 一对一识别旧谱面，保留原 ID；只改当前谱面 Hash 时同步修正原来附着的成绩 Hash。 |
| 歌曲 ID、标题、歌手、谱师、文本编码、封面 | OJN 文档与解码版本 | 解码策略升级后重新投影；封面文件引用由存储适配器更新。不得从旧标签反推 OJN 原值。 |
| 难度名、等级、列数、OD、BPM、长度、物件和长条数量 | OJN 难度、谱面时序与 O2Jam 投影规则 | 投影规则升级后逐字段原位重算；仅更新存在且可证明属于该 EX/NX/HX 的谱面。缺失或新增难度需要单独迁移策略。 |
| Mania 星级和最大连击 | Mania 计算器及其独立版本 | 算法版本变化时重算缓存，不改变 OJN 或成绩身份；等级颜色仍从 O2Jam 等级读取。 |
| 原生本地状态：`DateAdded`、`UserSettings`、`Hidden`、`LastPlayed`、收藏夹 | osu!lazer 与用户 | 不因重新解码或元数据重算覆盖；仅原生用户操作或明确的收藏夹同步规则可修改。 |
| 成绩、正式 v5 replay、成绩 ID/Hash/文件 | 原生 `ScoreInfo` 和回放存储 | 不重新生成成绩内容；源内容变化时保留旧 Hash 且不转挂。只对同一源、同一难度的旧共享 Hash 做一次映射。 |

原生 `BeatmapInfo.UpdateStatisticsFromBeatmap` 使用可玩长度和最常见 BPM；当前 OJN 投影使用声明/末音长度与初始 BPM，直接调用会改变现有曲库数据。原生 `BeatmapInfo.UpdateLocalScores` 仅按 Hash 重挂成绩；旧版三难度共享源 Hash 时，必须先利用已有关联分别迁移，不能用全局 Hash 匹配。文件存储、待删除 set 的清理和成绩记录保留继续复用原生实现。

## 已确定的更新规则

| 输入变化 | 当前行为 | 重构约束 |
|---|---|---|
| 同一源字节，重算标签、星级或编码 | 原位更新 set/难度，并将旧共享 Hash 的已关联成绩改为独立难度 Hash | 保留 set ID、难度 ID、成绩 ID、原生成绩关联；不得将 EX/NX/HX 的成绩串到另一难度。 |
| 源文件搬家，字节不变 | 刷新服务按长度和 SHA-256 找到旧 set，更新外部路径 | 保留原 IDs 和成绩；重复副本只保留一个活动 set。 |
| 同一路径的 OJN 字节改变 | 新建 set/难度，旧 set 标记 `DeletePending`；写入后旧成绩暂时关联旧谱面；下次启动时原生 Realm 清理会移除待删除 set 和谱面对象，成绩记录及旧 `BeatmapHash` 留下 | 用户确认旧成绩不得自动挂到新版谱面。即使只改元数据，当前也按源字节变化处理。历史成绩不会出现在新版谱面排行榜中；用户确认只保留成绩记录和旧 Hash，无需继续打开旧谱面。 |
| 源文件缺失或用户清理 O2Lazer 曲库 | 将本 ruleset 的 set 标记 `DeletePending`，原生启动清理随后移除这些 set 和谱面对象 | 不标记成绩删除；成绩的旧 `BeatmapHash` 保留。用户确认无需在客户端继续打开旧谱面。 |

2026-09-26 的临时 Realm 回归已验证：改动 OJN 的一处可玩物件并恢复原时间戳后，即使文件长度也不变，显式刷新仍会创建不同 ID/Hash 的新谱面；旧 set 待删除，同一会话内旧成绩的 ID、连击和旧谱面关联保持不变，新谱面没有继承成绩。临时库模拟重启还验证了原生 `RealmAccess` 清理会移除旧 set/谱面，成绩 ID、连击和旧 `BeatmapHash` 仍在，`ScoreInfo.BeatmapInfo` 变为 null。现有测试也覆盖同源旧 set 的单难度迁移、源文件搬家和缺失标记。完整三难度迁移、重复副本竞争与失败回滚尚未形成同等强度的临时库证据。

## 写入重设计前必须解决的缺口

1. **字段投影与版本**：上表已区分来源和不可覆盖的用户字段；`refreshMetadata` 仍只重算标题、作者、星级、部分标签、路径和 Hash。同源但算法变更时，难度名、等级载体、BPM、长度、物件数、背景等尚未统一重算。要将逐字段投影和版本迁移落实到写入器。
2. **身份判定**：旧版共用源 Hash、新版按难度 Hash、set hash 改版、原生 `BeatmapInfo.ID` 和 `ScoreInfo.BeatmapHash` 必须一同映射。仅凭路径、标签或一个 MD5 不能安全迁移。旧版存在无可玩物件但有块的难度，新版规划器只保留可玩难度，迁移时要决定如何保留其历史记录。
3. **刷新与重复**：显式刷新现已核对 OJN 源 SHA-256，时间戳和长度不变也可发现内容修改；这会增加一次顺序读取，仍须在大曲库实测扫描成本。已导入的 OJN 即使跳过写入，刷新结束也会撤销其 OJM 播放缓存，让下次选曲重读归档；OJM 内容不进入谱面身份 Hash，正在播放的曲目不热替换。相同内容的搬家与同时存在的副本走不同分支，重复副本竞争仍需验证。
4. **事务与文件**：`WriteBatch` 的 Realm 模型更改共用一笔事务，但原生 `RealmFileStore.Add` 在事务内把字节写入磁盘；数据库回滚不等于文件系统回滚。新后端需要为文件暂存、失败重试、孤儿文件回收定义边界。
5. **后端替换**：当前 `IO2JamLibraryWriter` 表示导入动作，不是数据模型或迁移协议。先形成源、set、难度、成绩和文件的后端中立身份/版本表，再在临时数据库验证更新、移动、重复、缺失和失败重试；不直接对用户库试迁移。

## 重设计草案的范围与分层

本轮先确定字段、身份、版本和恢复协议，随后分小步实现。继续使用宿主原生 Realm/文件库/成绩模型，不建立第二份成绩库，不预先实现 SQL 或本地/服务器档案。旧元数据只作为证明身份、原 ID 和用户状态的迁移输入；可重算字段重新从 OJN 投影，不继承旧实现的错误值。重构前测试 replay 不兼容，正式 v5 文件及已存成绩保持契约。

| 所有者 | 重设计后的责任 | 保留的边界 |
|---|---|---|
| Formats | OJN/OJM 解码结果 | 不认识导入版本、Realm、Mod、UI 或用户库 |
| Integration | 格式到运行谱面/采样引用的映射 | 不决定成绩迁移、持久化字段或数据库事务 |
| Host/Library | 源快照、导入投影、版本比较、同源难度匹配和操作计划 | 数据使用源哈希、难度编号、普通值和不透明 ID；不返回 Realm 托管对象 |
| Host/Difficulty | 无 Mod Mania 缓存与算法版本 | 不把 Lv/10 写入原生 StarRating，不决定 O2Jam 判定 |
| Host/Persistence/Realm | 原生字段赋值、关联核验、文件预留、事务、原生清理接入 | Realm 类型及具体查询只在适配器；原生模型编译耦合仍存在，不宣称已能直接换 SQL |
| Presentation | Lv 文本/颜色、筛选、标签与设置进度 | 消费已提交数据，不借显示文本决定迁移身份或写入版本 |

沿用并逐步整理 `O2JamImportPlan`、`O2JamImportedSource` 和现有写入契约；不先生成通用 ORM、全新谱面模型或跨 ruleset 存储接口。第二 ruleset 出现实际使用者后再提取公共设施。

## 统一字段投影

新增和同源刷新必须消费同一投影，不再各写一份赋值清单。源快照从同一组 OJN 字节得到 SHA-256、解码数据、源长度和文件内容；时间戳/路径作为位置提示一起捕获，不能在写入阶段用后来读取的文件时间给较早字节盖章。提交前发现源已经变化时中止该项并重试；文件系统本身不参与数据库事务，无法保证外部文件永远不变。

| 投影字段 | 写入目标与第一阶段规则 | 当前刷新缺口 |
|---|---|---|
| 源字节/SHA-256/文件名 | 原生文件库及 set 文件引用；文件哈希使用原生编码，难度 Hash 不作文件主键 | 已能写新文件；搬家仍与旧路径/set Hash 分支耦合 |
| SourceDirectory/文件名/源长度/源时间 | Metadata.Source、AudioFile、原生命名文件引用、源长度载体、LastLocalUpdate | 已更新部分字段；改为同一快照，不用写入时重读时间 |
| SongId、Title、Artist、Author | o2ma 搜索标签、标题/歌手/谱师；继续当前空标题文件名回退和空谱师 O2Jam 回退 | o2ma 标签未统一重算；不能直接修改可能被其他谱面共享的 Author.Username，应为目标谱面替换合适引用 |
| 难度编号、原 Lv、DifficultyName | 独立的结构化编号/Lv 值，难度名仍为现有英文固定存储格式；展示读原 Lv 后做颜色投影 | 目前依赖 DifficultyName 前缀识别槽位，且刷新不重写难度名 |
| CS/OD 与其他默认难度字段 | CS=7，OD=clamp(Lv,0,10)，其余继续现有原生默认值；这是宿主元数据，不是 Core 判定或 MS 的 OD/HP 基线 | 刷新不统一重写 |
| BPM | 保留当前初始 BPM 规则 | 未刷新；不能直接替换成原生最常见 BPM |
| Length | 保留当前 max(OJN 声明长度，解码音符/音频事件末位置换算时间+5000ms)，不把 BPM 事件当作末音 | 未刷新；本轮不改变统计口径或尾音长度行为 |
| TotalObjectCount/EndTimeObjectCount | 可演奏物件数/其中长条数，与现有规划器一致 | 未刷新 |
| 封面/缩略图回退 | 沿用 cover 优先、thumbnail 回退，更新文件引用和 Metadata.BackgroundFile；移除不再使用的自有命名引用，不直接删全局文件 | 同源刷新不更新封面 |
| Mania 星级/最大连击 | 无 Mod 基线写 StarRating，最大连击写现有缓存载体；继续原生 Mania 计算与当前适配版本 | 已部分刷新；将版本与有效值一起提交 |
| 系统标签与投影版本 | 只替换已登记的 O2Lazer 自有前缀及确定属于本源的 o2ma 标识 | 现有 clean 标记与不完整刷新混在一起，不能代表所有字段已更新 |
| 原生用户状态与额外字段 | 保留 set/难度 ID、DateAdded、UserSettings、Hidden、LastPlayed、BeatDivisor、用户标签及非导入拥有字段 | 不能用完整新对象覆盖旧对象，不能清空非自有标签 |
| 成绩/replay/收藏夹 | 仅按下节的已证明身份映射调整关联；成绩值、ID、文件及回放帧不重生成 | 尚缺三难度、歧义与集合迁移的完整证据 |

OJN 不提供独立的罗马字/Unicode 双份信息；第一阶段不新增自动转写策略，也不顺带重置已有 Unicode 或在线字段。其他元数据更新口径有新需求时另定版本和验收。读取投影的失败/冲突结果须使用现有本地化系统显示，不能在 Realm 写入器内组装产品文案。

## 版本设计

原生数据库 schema 版本属于 osu!，本 ruleset 不读取它来判断自身元数据是否更新，也不修改它。O2Lazer 的版本描述投影/缓存含义，不描述 Realm 的物理表结构。

| 版本 | 建议规则 | 触发的工作 |
|---|---|---|
| 投影载体格式 | 整数，从 1 起；解析字段结构发生不兼容变化才更新 | 选择适配器解析方式；未知更高格式不覆盖、不当成旧版自动降级 |
| 元数据投影算法 | 原生难度算法同类的单调整数，首版建议 20261001；按实际实现完成时定值，运行时不生成时间版本 | 同源字节的难度名、等级、统计、来源和媒体引用重算，不改变规范内容身份 |
| 文本解码策略 | 保留现有 encoding:2 的迁移语义，之后由解码接入策略独立递增 | 文本重投影；不触发新成绩身份 |
| 身份算法 | 当前源 SHA-256、难度 Hash/MD5 和 set Hash 规则冻结为版本 1 | 只有未来明确更改身份公式时才制定专门迁移；不随投影算法版本一起变 |
| Mania 缓存 | 继续使用原生 Mania Version 与现有 CacheVersion=Version*10+2 | 重算星级/最大连击，不替代投影版本 |
| replay | 正式 schema v5 保持不变 | 导入/读取验证；与上述元数据版本分开 |

Realm 原生模型不能随意增加持久化字段，当前适配器可将新增的投影版本、身份版本、难度编号及原 Lv 写为登记的 Tags token，例如 `o2lazer-projection:1:20261001`、`o2lazer-identity:1`、`o2lazer-chart:1:0`、`o2lazer-level:1:75`。这些是待实现的适配编码，不是后端中立契约本身；既有编码/Mania token 继续由各自策略管理，未来后端可直接使用列。

目录编码回退也是可变的解码输入。同一源字节和相同策略版本不保证目录上下文从未变化；准备投影时需要明确编码决定及是否依赖目录回退，对依赖上下文的旧文本在显式刷新时重验。不要把 encoding:2 单独当作所有文本无需重新检查的证明，也不要因重验文本就无条件重跑 Mania 计算。

读端先验证格式、版本、唯一 token、数值范围及源/槽位身份；同前缀重复或互相冲突不能取第一个就盖章。没有新标记的旧记录进入最小身份识别路径，不能直接认为已更新。标记只有在该难度全部应更新字段和缓存成功提交后写入；源级“已是当前版本”必须核对所有活动难度，不能只看某个难度的标签。旧 clean 标签只作兼容输入，不再用它证明新投影完成。

## 身份匹配与迁移规则

1. **验证所有者与内容**：规则集必须为 o2lazer，源身份从已存 OJN 文件引用/可验证旧记录得到。只靠路径或 set Hash 不足以证明同源；已知 set ID 也是查询提示，不是内容证明。混有其他 ruleset 难度的 set 不作为可整组改 Hash/标记删除的对象，先保留并报告冲突。
2. **识别槽位**：优先使用验证后的独立难度编号与源身份，其次使用源字节计算的规范 Hash/MD5。仅在有内容证据、已知旧写入格式且恰好唯一对应时允许旧名称回退；证据冲突、无候选或多候选保留原记录，不写“当前版本”。准备迁移时读取全部三槽位身份与可玩性，活动投影仍只包含可玩难度，不复制第二份音符模型。
3. **同源更新**：保留 set/难度 IDs、用户状态，统一重投影；搬家/改名与旧 set Hash 版本变化同时发生也应复用这些 IDs。当前 `containsSourceContent` 先要求同路径，这个门槛需在新内容匹配流程中解除，不能让迁移落到替换新 set 的路径。
4. **旧共享 Hash 成绩**：在改变难度 Hash 前快照原有明确关联，按已经证明的 EX/NX/HX 分别修正这些成绩的 BeatmapHash/关联。保持成绩 ID、分数、统计、Mods、日期、Rank 与文件。没有明确难度证据的未关联旧成绩保留旧 Hash，不在全库按共享 Hash 批量重挂。三个难度的映射须在同一模型事务完成。
5. **可玩槽位变化**：同源出现新增可玩难度才创建该难度的新 ID；已唯一识别、如今不可玩的旧槽位保留其成绩记录和历史 Hash，按原生模型生命周期移除相应谱面关联。未知槽位不推断成某个难度，也不自动清除。完全无可玩内容/解码失败时保留现有条目并报告，不能当作成功刷新。移除旧槽位属于待确认、待测试的迁移规则，当前实现没有执行。
6. **MD5 与收藏夹**：同源且槽位已确认才更新旧 MD5。旧 MD5 在库中唯一对应目标难度时复用原生 `TransferCollectionReferences`；多个难度或多个 ruleset 共用旧 MD5 时保留原集合引用并报告，不全局替换、不猜测用户想收藏哪个对象。自动文件夹收藏夹再走现有同步，不能删除用户集合。
7. **正式 v5 文件**：当前规范 Hash/MD5 公式不变，元数据版本更新不改归档字节。已经关联的成绩继续按原生记录读取回放；独立重新导入按 o2lazer 身份与 Hash/MD5 的唯一一致匹配，不能先按共享 Hash 任取一个就忽略 MD5。旧共享 Hash 可用有效独立 MD5 消歧；二者冲突或都无法唯一定位时明确不自动关联。未来若真要改规范身份算法，须另定归档身份映射与回归，本方案不预建 alias 数据库。
8. **内容改变/明确缺失**：沿用已确认政策——创建新内容身份后，旧成绩保留为历史，不挂新版；旧谱面对象最终可由原生清理。访问失败、不可达磁盘、解码失败或取消不是已证明缺失，不标记删除；不能把 `File.Exists=false` 单独当作整个扫描成功的证据。

新记录与旧记录都不依赖 Lv 颜色、显示难度名或当前 UI 语言来产生身份。身份不能由最终星数、成绩或文件夹名计算。

## 重复副本与操作顺序

扫描与准备按规范源 SHA-256 归组；当前会话的批内结果也更新索引，不能只使用刷新开始前的旧快照。相同内容的新路径不重复创建活动 set/难度；仍可用的已登记路径优先保留，原路径明确失效后才迁往扫描中成功验证的副本，选择顺序需固定，避免每次刷新路径抖动。

已有多个旧 set 时，不自动合并成绩、挑一个覆盖用户设置或删除其余记录。先检查逐难度身份和关联，作为迁移冲突保留；后续如需归并须单独明确规则。普通副本去重与旧库归并是不同操作。

一次有界批次分为：读取稳定源快照 → 解码/计算投影 → 准备身份与更新计划 → 核对当前数据库状态 → 文件预留 → 模型事务 → 提交后通知。事务开始时须重查所有者、内容、版本和已删除状态，不能只信任工作线程较早的快照。编码/计算失败不进入写入阶段，扫描不完整不做缺失清理。

取消只阻止尚未提交的批次；已提交批次保留，并完成缓存失效。提交后的监听器/缓存通知失败不等于数据库回滚，应单独诊断和重试通知，不能把已提交结果当成未写入。通知只发生在模型事务提交后，不随文件预留事务发生。

## 文件预留与失败恢复

原生 `RealmFileStore.Add` 已按内容哈希去重、校验旧文件，并通过 `Storage.CreateFileSafely` 写入，继续复用。具体缺口是文件落盘不能被 Realm 事务撤销：如果新的 RealmFile 行也随模型事务回滚，原生 `Cleanup()` 仅查询数据库内零引用行，无法发现这个未登记磁盘文件。

建议在 Realm 适配器中采用两个模型事务，不添加自有数据库 schema 或文件系统清理器：

1. **预留事务**：从已验证源/背景快照计算原生文件 Hash，查询并为缺少的 Hash 添加原生 RealmFile 行，提交后仍无命名引用。既有文件行及其他 ruleset 引用原样保留；本阶段没有谱面/成绩更改或刷新通知，也不写入文件字节。
2. **谱面事务**：确认预留行仍存在，再调用原生 `RealmFileStore.Add` 校验/安全写入文件，应用所有字段、成绩/收藏夹关联和命名引用，最后提交。同一数据库事务锁内原生清理不能同时移除预留行；如果开始前预留丢失则停止并重新准备，不能直接退回未预留写入。
3. **失败与重启**：模型事务失败时旧谱面/成绩保持原样；新预留行仍在且 Usages 为零。重试可按同一 Hash 复用已写文件，宿主下次启动的原生清理可回收零引用行及文件。若文件原本被其他对象使用，不得删除或降低其已有引用。

它提供模型事务原子性和可追踪文件恢复，不承诺数据库与文件系统共同原子提交。需要测试预留后取消、文件写入异常、第二条请求失败、提交前失败、重启清理及共享文件保护；在这些验证通过前不能部署到真实库。过去已经落盘但没有 RealmFile 行的孤儿不在自动回收范围，不全局扫描/删除原生文件库。

未来宿主后端改变时保留“先有可追踪记录，再发布引用”的恢复语义，按新原生文件库实现，不移植 Realm 具体类型或假定 SQL API。
